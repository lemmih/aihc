# aihc-haddock

Documentation tool for aihc packages, built as a proof of concept for
[issue #1895](https://github.com/ai-haskell-compiler/aihc/issues/1895).

It shares dependency resolution and source loading with the compiler through
`aihc-package-plan`, keeps its own artifact cache, and produces a versioned
machine-readable documentation model plus a Hoogle database. HTML output is
not part of this proof of concept. Mainline Haddock is the reference: the
comparison harness checks the model against Haddock's `--show-interface` JSON
and the Hoogle database against Haddock's `--hoogle` output.

## Usage

```
aihc-haddock build PACKAGE_DIR --json docs.json --hoogle docs.txt
aihc-haddock build colour-2.3.7 --no-deps --json colour.json
aihc-haddock compare-json docs.json reference/haddock.json
aihc-haddock compare-hoogle docs.txt reference/hoogle.txt
```

`build` documents the package and, unless `--no-deps` is given, its
dependencies. Every package is cached under the XDG cache directory
`aihc-haddock` (or `--store DIR`), keyed by the model format version, the
package sources and the dependency artifacts. The compare commands print a
report that starts with `PASS` or `FAIL n differences`, followed by one entry
per differing field and the notes that state what the comparison omitted.

## How comments are attached

The parser drops comments, so `Aihc.Haddock.Comment` recovers them from the
token stream and records the code token before and after each documentation
comment. `Aihc.Haddock.Build` walks the syntax tree and claims comments by
position:

- `-- |` documents the outermost documentable node that starts at the
  following token. Parents claim before their children.
- `-- ^` documents the innermost documentable node that contains the preceding
  token. Children claim before their parents. Separators (`,` and `;`) are
  skipped, so a comment after a field's comma documents the field.
- Layout is emulated with a column check: inside a layout block (the module,
  a class body) a `-- ^` at or left of the item column belongs to the enclosing
  item, not to the last argument type. Constructors, arguments and fields are
  not layout items, so any column works inside a data declaration.
- `-- $name` chunks are keyed by name; `-- *` sections are ordered by position
  inside the export list.
- GHC's lexer continues a documentation comment over every following `--` line
  except a `-- $name` header, so `-- *` bullets and `-- |` table rows inside a
  comment stay inside it.

Comments that attach to nothing become diagnostics on the module.

## Comparison and normalization

`Aihc.Haddock.Compare` converts both sides to one comparison model:

- Identities are module plus occurrence name. The package part of a Haddock
  stable name (`$pkg$Module$name`) is dropped because Haddock reports `main`
  for packages documented from source. Module aliases (`--module-alias
  FROM=TO`) map reference modules to aihc modules; a collision fails the
  comparison.
- Generated names such as `$fEqShape` and `$dmname` are excluded and listed.
- Documentation trees are flattened: nested `DocAppend` become one sequence,
  adjacent strings merge, empty documents disappear. Identifier links are
  compared by occurrence name until `aihc-resolve` is wired in.
- `exports` has set semantics. `visible_exports` order is compared for
  top-level names only, because GHC orders record fields alphabetically.
- A type and a constructor with the same name share one stable name in
  Haddock's JSON; the type's documentation is compared.
- The Hoogle layer compares declarations after collapsing whitespace and
  dropping module qualifiers from instance heads, and compares documentation
  as re-flowed text.

Fields not compared: `package_info`, `link_env`, `is_sig`, `info`, `options`.

## Fixtures

`test/Test/Fixtures/haddock/<name>/` holds a small cabal package, the mainline
Haddock outputs under `reference/` (generated by
`scripts/haddock-reference.sh` inside `nix develop`, with tool versions and
commands recorded in `environment.txt`), and the goldens under `expected/`:
the model JSON, the Hoogle database and the two comparison reports.
`expected/status.txt` states the expected verdict per layer as `PASS` or
`XFAIL <reason>`; an unexpected pass fails the test. Set
`AIHC_HADDOCK_ACCEPT=1` when running the test suite to rewrite the goldens.

| Fixture | JSON | Hoogle | Notes |
| --- | --- | --- | --- |
| `shapes` | PASS | PASS | Constructors, fields, argument docs, class methods, fixity, named chunk, sections |
| `layout` | PASS | PASS | Column-one `-- ^` after data, class and function declarations |
| `sections` | PASS | XFAIL | Header fields, `@since`, standalone deriving, DEPRECATED, explicit subordinate exports |
| `markup` | XFAIL | XFAIL | Every markup form; pattern synonym signatures lack spans in aihc-parser 3.0.0.0 |

## Not yet wired in

- Name resolution (`aihc-resolve`): identifier links, re-exports and
  cross-package links.
- Type information (`aihc-tc`): signatures of bindings without one, instance
  heads with resolved class identities, kinds.
- HTML output, table cell parsing, and the `colour` package comparison.
- The `DeclPatSynSig` span in `aihc-parser`.
